# 🤖 ออตโต้บอท คอนโทรล (Otto-Bot Control Web)

เว็บแอปภาษาไทยสำหรับควบคุมหุ่นยนต์ **Otto** (open-source robot) ผ่าน **MQTT (Mosquitto)**
พร้อมกล่องแชทที่ *พูดได้–ฟังได้* และสมองกลจาก **Generative AI**

สร้างด้วย Next.js 15 (App Router) + TypeScript

---

## ความสามารถ

| # | ความสามารถ | ทำงานอย่างไร |
|---|-----------|--------------|
| 1 | กล่องแชทที่ใช้ได้ทั้ง **TTS** และ **STT** | พูดเข้า: Web Speech API (`th-TH`) · อ่านออกเสียง: เรียก **API เสียงไทย** ฝั่งเซิร์ฟเวอร์ (Google / Azure / OpenAI / อื่น ๆ) ตั้งค่าที่ `config/tts.txt` |
| 2 | รับข้อความจากออตโต้บอทผ่าน MQTT มาเติมในกล่องแชท | หุ่นส่งมาที่ `ottobot/chat/in` → เซิร์ฟเวอร์ส่งต่อให้เบราว์เซอร์ทาง SSE |
| 3 | Generative AI ตั้งค่าผ่าน **ไฟล์ข้อความ** | `config/ai.txt` — กรอก `PROVIDER_URL` กับ `MODEL` (รองรับ API มาตรฐาน OpenAI) |
| 4 | AI ส่ง**ท่าทาง**และ**คำพูด**ไปหุ่น คนละ topic | ท่าทาง (JSON: ชื่อคำสั่ง + สีหน้า) → `ottobot/cmd`, คำพูด → `ottobot/speech` |
| 5 | เว็บส่งคำสั่งควบคุมไปหาหุ่นได้ | `ottobot/control/out` (ส่งอะไรก็ได้จากแท็บ *สั่งเอง*) — ฝั่งหุ่นยังไม่ต้องส่ง control กลับมา |
| 6 | แสดงสีหน้าปัจจุบันของหุ่น**มุมขวาบน** | จอ LED matrix 16×8 จำลอง อัปเดตจาก AI, จากหุ่น (`ottobot/face/state`) หรือเลือกเอง |

## เริ่มใช้งาน

```bash
npm install
npm run dev          # โหมดพัฒนา → http://localhost:3000
# หรือ
npm run build && npm start
```

### ตั้งค่า AI (ข้อ 3)

เปิดไฟล์ [`config/ai.txt`](config/ai.txt) แล้วกรอก:

```ini
PROVIDER_URL = https://api.openai.com/v1/chat/completions
MODEL        = gpt-4o-mini
API_KEY      = sk-xxxxxxxx
```

ตัวอย่าง provider อื่น ๆ ที่ใช้ได้ (ทุกตัวที่รองรับ `/chat/completions` แบบ OpenAI):

| ผู้ให้บริการ | PROVIDER_URL |
|---|---|
| OpenAI | `https://api.openai.com/v1/chat/completions` |
| OpenRouter | `https://openrouter.ai/api/v1/chat/completions` |
| Ollama (ในเครื่อง) | `http://localhost:11434/v1/chat/completions` |
| LM Studio (ในเครื่อง) | `http://localhost:1234/v1/chat/completions` |

> แก้ไฟล์เสร็จแล้ว **ไม่ต้องรีสตาร์ตเซิร์ฟเวอร์** — กดปุ่ม “🔄 โหลดค่าใหม่” ในแท็บ *ตั้งค่า* บนหน้าเว็บได้เลย
>
> ถ้าไม่ต้องการให้ค่าจริงถูก commit ให้สร้างไฟล์ `config/ai.local.txt` (อยู่ใน `.gitignore` แล้ว) ค่าในไฟล์นี้จะทับไฟล์หลัก

**ยังไม่ได้ตั้งค่าก็ใช้งานได้** — เว็บจะทำงานใน *โหมดออฟไลน์* ที่เข้าใจคำสั่งง่าย ๆ เช่น
“สวัสดี”, “เต้น”, “เดินหน้า”, “โบกมือ”, “กระโดด”, “นอน”

### ตั้งค่าเสียงพูดภาษาไทย (TTS)

เสียงไทยที่ติดมากับเบราว์เซอร์คุณภาพต่ำมาก เว็บจึงเรียก API เสียงจากฝั่งเซิร์ฟเวอร์แทน

**ค่าเริ่มต้นใช้งานได้ทันทีโดยไม่ต้องตั้งค่าอะไรเลย** — [`config/tts.txt`](config/tts.txt) ตั้งมาเป็น:

```ini
PROVIDER = edge
VOICE    = th-TH-PremwadeeNeural
```

`edge` คือบริการอ่านออกเสียงของเบราว์เซอร์ Microsoft Edge **ฟรี ไม่ต้องสมัคร ไม่ต้องใช้ API key**
และได้เสียงไทยคุณภาพเดียวกับ Azure

> ⚠️ ข้อจำกัด: ช่องทางนี้ไมโครซอฟท์ไม่ได้เปิดเป็น API สาธารณะ อาจใช้ไม่ได้วันไหนก็ได้
> และไม่เหมาะกับงานเชิงพาณิชย์ ถ้าต้องการความมั่นคงให้ใช้ `google` หรือ `azure` แทน

| PROVIDER | ค่าที่ต้องกรอก | เสียงไทยแนะนำ | ค่าใช้จ่าย |
|---|---|---|---|
| **`edge`** ⭐ | **ไม่ต้องกรอกอะไร** | `th-TH-PremwadeeNeural` (ญ), `th-TH-NiwatNeural` (ช) | **ฟรี ไม่ต้องสมัคร** |
| `google` | `API_KEY` | `th-TH-Neural2-C`, `th-TH-Standard-A` | ฟรี ~1 ล้านตัวอักษร/เดือน (ต้องผูกบัตร) |
| `azure` | `API_KEY`, `REGION` | `th-TH-PremwadeeNeural`, `th-TH-NiwatNeural` | ฟรี ~500,000 ตัวอักษร/เดือน (ต้องผูกบัตร) |
| `openai` | `API_KEY` | `nova`, `shimmer` (ติดสำเนียงต่างชาติ) | เสียเงิน |
| `custom` | `PROVIDER_URL` | ผู้ให้บริการไทยอื่น ๆ เช่น Botnoi Voice | แล้วแต่เจ้า |
| `browser` | ไม่ต้องกรอก | ใช้เสียงเบราว์เซอร์แบบเดิม | ฟรี แต่ฟังไม่ค่อยรู้เรื่อง |

โหมด `custom` เว็บจะส่ง `POST` เป็น JSON `{ text, voice, lang, speed }` ไปที่ `PROVIDER_URL`
แล้วรับกลับได้ทั้งไฟล์เสียงตรง ๆ, JSON ที่มี base64 (`audioContent` / `audio` / `data`)
หรือ JSON ที่มีลิงก์ (`audio_url` / `url` / `link`)
ถ้าผู้ให้บริการใช้ header อื่นแทน `Authorization` ให้ตั้ง `AUTH_HEADER` และ `AUTH_PREFIX`
(เช่น Botnoi Voice ใช้ `AUTH_HEADER = Botnoi-Token` และ `AUTH_PREFIX =` ว่าง)

> ถ้าเรียก API ไม่สำเร็จ เว็บจะถอยไปใช้เสียงของเบราว์เซอร์ให้อัตโนมัติ พร้อมขึ้นข้อความแจ้งสาเหตุ

### ตั้งค่า MQTT

เปิดไฟล์ [`config/mqtt.txt`](config/mqtt.txt)

**แบบที่ 1 — ในวงแลนเดียวกัน (Mosquitto)**

```ini
BROKER_URL = mqtt://localhost:1883
USERNAME   =
PASSWORD   =
```

**แบบที่ 2 — ข้ามเครือข่ายด้วย HiveMQ ที่ติดตั้งเอง** ⭐

เว็บกับหุ่นไม่ต้องอยู่วง WiFi เดียวกัน ทั้งสองฝั่งต่อเข้าหา broker กลางตัวเดียวกัน

**1. รัน HiveMQ** — วาง license ไว้ในโฟลเดอร์ `license/` แล้วสั่ง `./bin/run.sh`

| พอร์ต | ใช้ทำอะไร |
|---|---|
| 1883 | MQTT ธรรมดา ไม่เข้ารหัส |
| **8883** | **MQTT over TLS** ← ใช้ตัวนี้ถ้าจะข้ามเครือข่าย |
| 8000 | WebSocket (เว็บนี้ไม่ต้องใช้ เพราะต่อจากฝั่งเซิร์ฟเวอร์) |

**2. เปิดการยืนยันตัวตน** — HiveMQ ที่ยังไม่ตั้งค่าอะไรจะ**ให้ทุกคนต่อได้โดยไม่ต้องใส่รหัส**
ให้เปิด extension สำหรับ username/password (File RBAC) แล้วสร้างบัญชีไว้
วิธีตั้งค่าดูในเอกสาร HiveMQ รุ่นที่คุณใช้ หัวข้อ *Security / Authentication*

**3. ทำให้เข้าถึงจากนอกบ้านได้** — เลือกทางใดทางหนึ่ง เรียงจากปลอดภัยที่สุด

| วิธี | ข้อดี | ข้อควรระวัง |
|---|---|---|
| **VPN** (Tailscale / WireGuard) ⭐ | ไม่ต้องเปิดพอร์ตออกเน็ตเลย ตั้งง่ายสุด | ต้องลง VPN ที่หุ่นด้วย |
| Port forward 8883 + DDNS | ไม่ต้องลงอะไรเพิ่มที่หุ่น | พอร์ตจะถูกสแกนจากทั่วโลกภายในไม่กี่ชั่วโมง — **ต้องเปิด TLS และตั้งรหัสผ่านก่อนเสมอ** |
| ย้าย broker ไป VPS | ได้ IP จริงถาวร ขอใบรับรอง Let's Encrypt ได้ | มีค่าเช่ารายเดือน |

**4. กรอกค่าลงไฟล์**

```ini
BROKER_URL = mqtts://ที่อยู่ของ broker:8883
USERNAME   = บัญชีที่สร้างไว้
PASSWORD   = รหัสผ่านของบัญชีนั้น
QOS        = 1
```

**เรื่องใบรับรอง TLS** — broker ที่ติดตั้งเองมักใช้ใบรับรองที่ออกเอง (self-signed)
ซึ่งตรวจไม่ผ่านโดยปริยาย ให้เลือกอย่างใดอย่างหนึ่ง:

```ini
CA_FILE = /path/ไปยัง/ca.pem     # แนะนำ — ยังตรวจใบรับรองอยู่
REJECT_UNAUTHORIZED = false      # ง่ายกว่า แต่ไม่กันการปลอมตัวเป็น broker
```

ถ้าใบรับรองมาจาก Let's Encrypt หรือ CA สาธารณะ ไม่ต้องตั้งทั้งสองอย่าง

> 🔒 **ห้ามใส่รหัสผ่านจริงใน `config/mqtt.txt` ถ้าจะ push ขึ้น git**
> ให้สร้าง `config/mqtt.local.txt` ใส่แค่ `USERNAME` กับ `PASSWORD`
> ไฟล์ `.local.txt` อยู่ใน `.gitignore` และจะทับค่าในไฟล์หลักให้อัตโนมัติ
>
> ⚠️ เว็บจะเตือนให้เองถ้าตั้งค่าแล้วเสี่ยง เช่น ชี้ไป broker นอกวงแลนโดยไม่ใส่รหัสผ่าน
> หรือยังต่อแบบไม่เข้ารหัส

ฝั่งหุ่น (ESP32) ต้องต่อไปที่ host / พอร์ต / บัญชีเดียวกัน
ดูโค้ดตัวอย่างได้ที่ท้ายไฟล์ [`config/topics.txt`](config/topics.txt)

ตัวเลือกเพิ่มเติมสำหรับการต่อแบบเข้ารหัส: `PROTOCOL_VERSION` (4 หรือ 5), `KEEPALIVE`,
`CONNECT_TIMEOUT_MS`, `REJECT_UNAUTHORIZED` และ `CA_FILE` (สำหรับ broker ที่ออกใบรับรองเอง)

เว็บเชื่อมต่อ broker **จากฝั่งเซิร์ฟเวอร์ (Node.js)** ผ่าน TCP ตามปกติ
จึง **ไม่ต้อง** เปิด listener แบบ WebSocket ใน Mosquitto และไม่มีปัญหา CORS
เบราว์เซอร์รับข้อความต่อผ่าน Server-Sent Events ที่ `/api/mqtt/stream`

## สัญญาการสื่อสาร MQTT (สำหรับคนเขียนเฟิร์มแวร์ฝั่งหุ่น)

ชื่อ topic ทั้งหมดแก้ได้ในไฟล์ `config/mqtt.txt`

### เว็บ → หุ่นยนต์

**`ottobot/cmd`** — คำสั่งท่าทางและสีหน้า (ข้อ 4)

```jsonc
{
  "motion": "walk",        // ชื่อคำสั่ง 1 ใน 13 ตัวด้านล่าง
  "face": "happy",         // สีหน้าที่จะแสดง
  "ts": 1700000000000
}
```

คำสั่งท่าทางที่ใช้ได้ (ฝั่งเฟิร์มแวร์เป็นคนกำหนดว่าแต่ละคำสั่งขยับอย่างไร):

| คำสั่ง | ความหมาย | คำสั่ง | ความหมาย |
|---|---|---|---|
| `walk` | เดินหน้า | `shake` | สะบัดขา |
| `back` | เดินถอยหลัง | `moonwalk` | มูนวอล์ก |
| `left` | เลี้ยวซ้าย | `wave` | โบกมือ |
| `right` | เลี้ยวขวา | `handsup` | ยกมือขึ้น |
| `home` | ท่ายืนปกติ | `handdown` | เอามือลง |
| `swing` | โยกตัว | `bend` | ก้มตัว |
| `updown` | ย่อ-ยืด | | |

* เว็บตรวจชื่อคำสั่งให้แล้ว ค่าที่หุ่นได้รับจะอยู่ใน 13 ตัวนี้เสมอ ไม่มีชื่อแปลกปลอม
* ถ้าเป็นการสั่ง**เปลี่ยนสีหน้าอย่างเดียว** จะไม่มีคีย์ `motion` มาด้วย เช่น `{"face":"love","ts":...}`
  → ให้เช็คว่ามีคีย์ `motion` หรือไม่ ก่อนสั่งขยับทุกครั้ง
* ถ้า AI ตอบโดยไม่ต้องขยับตัว จะไม่มีข้อความส่งมาที่ topic นี้เลย

**`ottobot/speech`** — ข้อความที่ให้หุ่นพูด (ข้อ 4)

```json
{ "text": "สวัสดีครับ", "face": "happy", "lang": "th-TH", "ts": 1700000000000 }
```

**`ottobot/control/out`** — คำสั่งควบคุมจากเว็บไปหุ่น (ส่งอะไรก็ได้จากแท็บ *สั่งเอง*)

### หุ่นยนต์ → เว็บ

**`ottobot/chat/in`** — ข้อความที่จะไปโผล่ในกล่องแชท (ข้อ 2)

ส่งเป็นข้อความเปล่าก็ได้ หรือเป็น JSON:

```json
{ "text": "สวัสดีครับ ผมได้ยินเสียงคุณแล้ว", "face": "happy" }
```

> ถ้าเปิดสวิตช์ **“⚡ ตอบหุ่นอัตโนมัติ”** (ค่าเริ่มต้น: เปิด) ข้อความที่เข้ามาทาง topic นี้
> จะถูกส่งต่อให้ AI ตอบ แล้วเว็บจะ publish คำพูด + ท่าทางกลับไปให้หุ่นทันที
> ครบวงจร: *หุ่นได้ยิน → เว็บคิด → หุ่นพูดและขยับ*

**`ottobot/face/state`** — สีหน้าปัจจุบันของหุ่น สำหรับแสดงมุมขวาบน (ข้อ 6)

ส่งเป็นข้อความเปล่า เช่น `happy` หรือ JSON `{"face":"happy"}`

**`ottobot/status`** — สถานะทั่วไป เช่น `{"battery":88,"distance":12}` จะขึ้นเป็นข้อความแจ้งเตือนสั้น ๆ

### สีหน้าที่รองรับ

`neutral` `happy` `sad` `angry` `surprised` `love` `sleepy` `confused` `wink` `cool`

## ทดสอบโดยไม่มีหุ่นจริง

```bash
# ส่งข้อความจาก "หุ่น" เข้ากล่องแชท
mosquitto_pub -h localhost -t ottobot/chat/in -m 'สวัสดีครับ ผมออตโต้'

# เปลี่ยนสีหน้ามุมขวาบน
mosquitto_pub -h localhost -t ottobot/face/state -m 'love'

# ดูสิ่งที่เว็บส่งออกไปหาหุ่น
mosquitto_sub -h localhost -t 'ottobot/#' -v
```

## หมายเหตุเรื่องเสียง

* **STT (ฟัง)** ใช้ได้บน **Chrome / Edge** เท่านั้น (Firefox ยังไม่รองรับ `SpeechRecognition`)
  และต้องรันบน `http://localhost` หรือ **HTTPS** เบราว์เซอร์จึงจะให้ใช้ไมโครโฟน
* **TTS (พูด)** ถ้าตั้งค่า `config/tts.txt` แล้ว เสียงจะมาจาก API ฝั่งเซิร์ฟเวอร์
  ใช้ได้ทุกเบราว์เซอร์และไม่ต้องติดตั้งเสียงไทยในเครื่อง
* ถ้ายังไม่ได้ตั้งค่า จะถอยไปใช้เสียงในตัวเบราว์เซอร์ ซึ่งเสียงไทยมักฟังไม่ค่อยรู้เรื่อง
* เบราว์เซอร์อาจบล็อกการเล่นเสียงอัตโนมัติจนกว่าผู้ใช้จะคลิกที่หน้าเว็บสักครั้ง
  ถ้าโดนบล็อก เว็บจะขึ้นข้อความบอกให้
* **อิโมจิจะถูกตัดออกก่อนอ่านออกเสียงเสมอ** ระบบจึงไม่อ่านชื่ออิโมจิออกมา
  ทั้งเสียงบนเว็บและข้อความที่ส่งไปให้หุ่นพูดที่ `ottobot/speech`
  (ในกล่องแชทยังแสดงอิโมจิตามปกติ)

src/
  app/
